# Issue tracker: my-specs trong docs-erp

Việc của hệ ERP không nằm trên GitHub Issues. Bốn repo `erp-hanh/*` đều
không có issue nào. Việc sống dưới dạng file markdown trong `docs-erp`.

## Quy ước

- Spec và plan: `docs-erp/99-meta/my-specs/YYYY-MM-DD-<slug>-design.md`
  và `YYYY-MM-DD-<slug>-plan.md`. Luôn đi theo cặp design + plan.
- Bàn giao giữa các phiên: `docs-erp/99-meta/YYYY-MM-DD-ban-giao*.md`.
  Phiên mới đọc file ban-giao mới nhất trước khi làm gì.
- Spec đã đóng của các chặng cũ: `docs-erp/99-meta/specs/`. Chỉ đọc,
  không ghi thêm vào đây.
- Không có nhãn triage. Skill `triage` chưa cài.

## Khi skill nói "publish to the issue tracker"

Tạo file mới trong `docs-erp/99-meta/my-specs/` theo đúng tên
`YYYY-MM-DD-<slug>-plan.md`. Ngày lấy từ ngày thật, không bịa.

## Khi skill nói "fetch the relevant ticket"

Đọc file được trỏ tới. Người dùng thường đưa thẳng đường dẫn hoặc tên chặng.
